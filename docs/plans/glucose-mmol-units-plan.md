**Цель:** значения глюкозы вводятся, хранятся и показываются в mmol/L как есть, без деления на 18. Сейчас ввод 5.6 отображается как 0.3, потому что отображение считает хранимое значение mg/dL.

**Архитектура:**

- Причина бага: быстрый ввод (`HealthQuickEntryModal.vue`) сохраняет mmol/L, а демо-данные (`scripts/generate-demo-data.mjs` → `public/data/demo.json`) хранятся в mg/dL; отображение делит на 18 в трёх местах: `app/utils/health-line-chart/glucose.ts`, `app/components/GlucoseTable.vue`, `app/components/DashboardMetricsGrid.vue`.
- Единица хранения — mmol/L. Деление на 18 удаляется из отображения.
- Старые записи в mg/dL переводятся одним правилом: значение `> 30` считается mg/dL и заменяется на `round(value / 18, 1)`; значение `≤ 30` не меняется. Правило живёт в одной функции в `app/lib/db/` и применяется в двух местах: миграция Dexie `version(3)` (уже сохранённые записи) и импорт JSON (старые файлы экспорта).
- Миграция: `this.version(3).stores({}).upgrade(tx => tx.table('glucoseMeasurement').toCollection().modify(...))` — индексы не меняются, существующие версии не трогаются. Проверено по документации Dexie (context7): `upgrade()` выполняется в транзакции обновления только при открытии БД старой версии; при ошибке вся транзакция откатывается. На новой пустой БД апгрейдер не запускается, а автосид берёт уже переведённый `demo.json`.

**Технологии:** Dexie (`Version.upgrade`, `Collection.modify`). Новых зависимостей нет.

## Решения пользователя

- **Единица:** прямой ввод в mmol/L, никаких пересчётов при отображении.
- **Существующие записи в браузере:** миграция Dexie с порогом `> 30` → mg/dL; то же правило при импорте JSON.
- **Разбиение работы:** две задачи; эта — первая. Вторая (`feat/ui-layout-refresh`: меню-дропдаун, карточки-ссылки, шрифт единиц, графики) — отдельным планом после этой.
- **Ветка:** `fix/glucose-mmol-units` от актуального `main`.

## Принятые предложения

1. **Порог 30:** физиологически mmol/L выше 30 почти не встречается, а mg/dL ниже 30 — тяжёлая гипогликемия, которой нет в демо и вряд ли есть в реальных данных. Диапазон 20–30 теоретически неоднозначен; принимаем, что такие значения уже в mmol/L.
2. **Округление до 0.1** при переводе (как и при отображении `toFixed(1)`), чтобы в базе не было значений вида `5.0555…`.
3. **(Пересмотрено 2026-11-09 по код-ревью, см. задачу 8)** ~~Формат экспорта остаётся `version: 1`~~. Было: формат экспорта остаётся `version: 1`: новые файлы уже в mmol/L, а старые файлы корректно переводятся правилом порога при импорте. Отдельная версия формата не нужна.
4. **Функция правила:** новый файл `app/lib/db/glucose-units.ts` с `normalizeGlucoseValue(value: number | null): number | null` и `normalizeGlucoseMeasurement(record)`.
