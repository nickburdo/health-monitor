# Улучшение скиллов и агента browser-checker по итогам задачи confirm-dialog — план реализации

> **Статус:** ✅ Одобрен пользователем 2026-10-22, выполнен 2026-10-22.
>
> **Для агентов-исполнителей:** используйте superpowers:executing-plans для выполнения плана задача за задачей. Шаги используют синтаксис чекбоксов (`- [ ]`). **Без TDD**: автоматические тесты не пишутся. Код-ревью выполняет скилл finish-task в последней задаче; проверка в браузере не нужна (UI приложения не меняется).
>
> **Контрольные точки (обязательно):** остановиться, кратко отчитаться и ждать явного подтверждения пользователя после каждой контрольной точки. Объединение: КТ1 (после задач 1–2); остальные задачи — по одной точке. Задачи внутри одной контрольной точки выполняются подряд.

**Цель:** закрыть пробелы, найденные при работе над `feat/confirm-dialog` (PR #19): start-task не проверяет бэклог и не объясняет правки документации, finish-task не фиксирует уровень ревью и не ревьюит исправления, browser-checker сокращает проверку тем, ширин и вариантов сценария, а остановка после каждой мелкой задачи даёт лишние подтверждения.

**Архитектура:** меняются только инструкции: `.claude/skills/start-task/SKILL.md`, `.claude/skills/start-task/plan-template.md`, `.claude/skills/finish-task/SKILL.md`, `.claude/agents/browser-checker.md` и правило о контрольных точках в памяти. Код приложения не меняется.

**Технологии:** новых зависимостей нет.

## Решения пользователя

- **start-task:** искать похожий пункт в бэклоге; объяснять в плане, зачем каждая правка документации.
- **finish-task:** зафиксировать уровень и исполнителя код-ревью; ревьюить исправления, сделанные по итогам ревью.
- **browser-checker:** тема обязательно через кнопку и через тему ОС; ширины из задания дополняют стандартные; все варианты сценария проходятся полностью.
- **Контрольные точки:** разрешить объединять мелкие задачи в одну контрольную точку (явно в плане, одобряется вместе с ним).
- **Хранение плана:** этот файл в `docs/plans/` — разовое исключение из правила «chore без файла плана», потому что реализация переносится на следующий день.
- **Ветка:** `chore/skills-review-followups` от актуального `main` (создана 2026-10-21).

## Принятые предложения (решены 2026-10-22)

1. **Исключение для chore в start-task:** закрепить в скилле, что план chore / docs сохраняется в `docs/plans/<name>-plan.md`, если реализация откладывается на другую сессию.
2. **Уровень ревью:** основное ревью — `code-review` уровня `medium` в субагенте general-purpose; ревью исправлений — уровня `low` только на изменениях после первого ревью.
3. **Формат «зачем»:** у задач, меняющих `CLAUDE.md` или `docs/`, строка `**Зачем:** <одно предложение>` сразу под строкой `**Файлы:**`.
4. **Формат группировки:** в шаблоне плана по умолчанию контрольная точка — каждая задача; объединение помечается строкой `**Контрольная точка:** КТn (после задач X–Y)` и перечисляется в шапке плана. Объединять можно только задачи без рискованных изменений (стили, подключение, документация), задачи с логикой — отдельной точкой.
5. **Бэклог при старте:** если найден похожий пункт, план явно говорит, что с ним сделать (удалить, сузить или отметить частично выполненным, как пункт про тёмную тему), и это выполняется в задаче документации, а не молча на завершении.
